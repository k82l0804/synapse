## Context

With the daemon running and specialists writing artifacts, there's no way to find
what's been produced without knowing the exact file paths. The artifact index solves
this by maintaining a DB table that mirrors what's on disk. The key behavior is
*mismatch halts* — it never silently resolves conflicts. `synapse artifacts <product>`
is the user-facing query command. Incremental indexing (called after each step) keeps
the index current without rescanning everything.

## Deliverables

### D-1: Filesystem scanner

**Files to change:**
- `src/index/scanner.ts` — NEW FILE — `scanArtifacts(repoPath): ArtifactFile[]`

**Scanned directories:**
```
{repo}/specs/              → type: spec
{repo}/plans/current/      → type: plan
{repo}/plans/done/         → type: plan
{repo}/reviews/spec/       → type: review
{repo}/reviews/plan/       → type: review
{repo}/reviews/code/       → type: review
{repo}/reviews/triage/     → type: review (triage)
{repo}/reviews/feedback/   → type: feedback
{repo}/tasks/current/      → type: task
{repo}/tasks/done/         → type: task
{repo}/tasks/deferred/     → type: task (deferred)
```

**Implementation notes:**
- Reads only `.md` files (skip `.gitkeep`, `README.md`, non-markdown)
- For each file: extract `id`, `name`, `status` from YAML frontmatter if present
  (use simple regex — not a full YAML parser — to read frontmatter block)
- Returns `ArtifactFile[]`: `{ type, filePath, id, name, status, createdAt }`
- `createdAt` = file mtime if not in frontmatter

**Spec contract ref:** AC-1, HLT-1, HLT-2

### D-2: Index builder — upsert artifacts table

**Files to change:**
- `src/index/builder.ts` — NEW FILE — `buildIndex(db, productId, repoPath): IndexResult`

**Implementation notes:**
- Calls `scanArtifacts(repoPath)`, then for each file:
  - `INSERT OR REPLACE INTO artifacts (product_id, type, file_path, status, created_at) VALUES (...)`
- Delete rows from `artifacts` where `file_path` no longer exists on disk (ghost records)
- Return `{ indexed: N, removed: N }`

**Spec contract ref:** AC-1, AC-6, HLT-3

### D-3: Mismatch detector

**Files to change:**
- `src/index/mismatch.ts` — NEW FILE — `detectMismatches(db, productId): Mismatch[]`

**Implementation notes:**
- For each artifact in `artifacts` table: read the file and parse its frontmatter `status`
- Compare to `artifacts.status` in DB
- If different: add to mismatch list
- `Mismatch`: `{ filePath, dbStatus, fileStatus }`
- Called during startup scan — if any mismatches found: print report and exit process

**Report format:**
```
[MISMATCH] artifacts table out of sync:
  specs/S-011-product-registration.md: DB=shipped, file=draft
  plans/current/2026-09-28T17-51_plan-T-2-1.md: DB=pending, file=approved

  Resolve: edit file status to match DB (or delete the DB row)
  Run: synapse repair --dry-run to preview corrections
```

Note: `synapse repair` is a future feature — just mention it in the message.

**Spec contract ref:** AC-5, HLT-4
