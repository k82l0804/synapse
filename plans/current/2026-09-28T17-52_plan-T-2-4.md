## Context

The daemon (T-2-3) transitions to `GATE_WAITING` state when it reaches a gate step
(spec review, plan review). It writes a WAITING file but has no mechanism to receive
the human's response. This plan implements the CLI commands the developer uses to
resolve gates: `synapse inbox`, `synapse approve`, and `synapse reject`.

The WAITING file path established in T-2-3: `.synapse/run/WAITING`

## Deliverables

### D-1: WAITING file writer (daemon side)

**Files to change:**
- `src/daemon/state.ts` — UPDATE — add `writeWaitingFile(repoPath, runId, gateType, artifactPath)`

**WAITING file content:**
```
type: GATE_WAITING
run: {run-id}
task: {task-id} {task-title}
gate: {gate-type}   # spec-review | plan-review | code-review
artifact: {absolute-path-to-artifact}
since: {ISO-timestamp}
```

**Implementation notes:**
- Written to `{repo-path}/.synapse/run/WAITING`
- One WAITING file per product at a time (overwritten on new gate — only one active gate per product)
- Deleted by approve/reject handler, not by the daemon directly

**Spec contract ref:** HLT-1

### D-2: `synapse inbox` — list all waiting gates

**Files to change:**
- `src/cli/commands/inbox.ts` — NEW FILE — `inbox(opts: { count: boolean }): void`
- `src/cli/index.ts` — UPDATE — wire `inbox` and `inbox --count` commands

**Implementation notes:**
- Reads all registered products from `repos.yaml`
- For each: checks if `{product-path}/.synapse/run/WAITING` exists
- Parses WAITING file content, formats output:
  ```
  2 gate(s) waiting

  [run-abc123] my-project — plan-review
    Artifact: plans/current/2026-09-28T17-51_plan-T-2-1.md
    Waiting since: 2026-09-28T17:00:00

  [run-def456] other-project — spec-review
    Artifact: specs/S-011-product-registration.md
    Waiting since: 2026-09-28T16:00:00
  ```
- `--count`: prints integer only (`2`)

**Spec contract ref:** AC-1, AC-5, HLT-2

### D-3: `synapse approve <run-id>`

**Files to change:**
- `src/cli/commands/approve.ts` — NEW FILE — `approve(runId: string, opts: { note?: string }): void`
- `src/cli/index.ts` — UPDATE — wire `approve` command

**Implementation notes:**
- Look up run-id in `pipeline_runs` table
- Error if not found: `error: unknown run ID 'xyz'` → exit 1
- Error if not in `waiting` status: `error: run 'xyz' is not waiting for approval` → exit 1
- Transition: `pipeline_runs.status = 'running'`, advance `current_step` to next step
- Delete the WAITING file at `{product-path}/.synapse/run/WAITING`
- Update `products.pipeline_status = 'running'`
- Print: `✓ Approved. Pipeline continuing from step: {next-step}`

**Spec contract ref:** AC-2, HLT-3

---

### D-4: `synapse reject <run-id> --note "..."`

**Files to change:**
- `src/cli/commands/reject.ts` — NEW FILE — `reject(runId: string, opts: { note: string }): void`
- `src/cli/index.ts` — UPDATE — wire `reject` command

**Implementation notes:**
- `--note` is REQUIRED — if absent or empty string: print `error: rejection requires --note with non-empty text` → exit 1
- Look up run-id → error if not found or not waiting
- Write feedback file: `{product-path}/reviews/feedback/YYYY-MM-DDTHH-MM_{gate-type}-{run-id}.md`
  ```markdown
  # Feedback: {gate-type} {run-id}

  > **Author:** Human  
  > **Rejected artifact:** `{artifact-path}`  
  > **Date:** {ISO timestamp}  
  > **Run ID:** {run-id}

  ## Rejection Note

  {note text}

  ## Required Before Next Iteration

  (Agent must read this before regenerating)
  ```
- Set `pipeline_runs.status = 'running'`  — daemon re-runs the SAME step (regeneration)
- Do NOT delete WAITING file — daemon recreates it when regeneration produces a new artifact
- Print: `✗ Rejected. Feedback written. Agent will regenerate {gate-type}.`

**Spec contract ref:** AC-3, AC-4, HLT-4
