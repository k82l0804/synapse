## Context

No signal parsing exists in the codebase today. The `src/cli/index.ts` is a stub
that prints help text and exits. `synapse.db` does not yet exist — this plan creates
the database schema alongside the parser. The signal grammar is fully specified in
`specs/pipeline-signal-protocol.md` including the exact regex patterns.

The parser is a pure utility module: it takes a file path, reads only the last line,
and returns a typed result. It has no side effects beyond reading a file. This makes
it the ideal first feature to implement — no daemon, no CLI, no DB needed to test it.

### D-2: Implement `readLastLine(filePath)`

**Files to change:**
- `src/signal/reader.ts` — NEW FILE — efficient last-line reader

**Implementation notes:**
- Must NOT read the entire file — use `fs.statSync` for size, then `fs.readSync` from
  `max(0, size - 4096)` to get the tail, split on `\n`, take the last non-empty line
- Handle edge case: file shorter than 4096 bytes → read entire file
- Returns `string` (the last line) or `null` if file is empty/does not exist

**Spec contract ref:** AC-5, HLT-1

### D-3: Implement `parsePipelineSignal(line)` and `parseTesterSignal(line)`

**Files to change:**
- `src/signal/parser.ts` — NEW FILE — signal parsers

**Implementation notes:**
- `PIPELINE_SIGNAL` regex (from `specs/pipeline-signal-protocol.md`):
  ```
  /^<!--\s*PIPELINE_SIGNAL:\s*STATUS=(\w+)\s+AUTO-FIX=(\d+)\s+ESCALATE=(\d+)\s*-->$/
  ```
- `TESTER_SIGNAL` regex:
  ```
  /^<!--\s*TESTER_SIGNAL:\s*PASS=(\d+)\s+FAIL=(\d+)\s+SKIPPED=(\d+)\s+TYPECHECK=(green|red)\s*-->$/
  ```
- Both return typed results or `null` (never throw)
- `STATUS` must be one of `DONE`, `PARTIAL`, `FAILED` — reject other values
- `TYPECHECK` must be `green` or `red` — regex enforces this

**Spec contract ref:** AC-1, AC-2, AC-6, HLT-2, HLT-3

### D-4: Implement `parseSignal(artifactPath)` — the public API

**Files to change:**
- `src/signal/index.ts` — NEW FILE — public API combining reader + parsers

**Implementation notes:**
- Calls `readLastLine(path)`, tries `parsePipelineSignal`, then `parseTesterSignal`
- Returns union type: `{ type: 'pipeline', ... } | { type: 'tester', ... } | { type: 'absent', reason: 'SIGNAL_ABSENT' | 'SCHEMA_VIOLATION', line: string | null }`
- `SCHEMA_VIOLATION` = last line starts with `<!-- PIPELINE_SIGNAL` or `<!-- TESTER_SIGNAL` but fails full parse
- `SIGNAL_ABSENT` = last line doesn't start with either prefix

**Spec contract ref:** AC-3, AC-4, HLT-4, HLT-5
